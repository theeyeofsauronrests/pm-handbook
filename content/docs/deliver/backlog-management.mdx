---
title: Backlog Management
description: How PMs keep the backlog current, prioritized, and useful.
---

The backlog is a prioritized expression of intent.

It reflects what the team believes is worth doing, in what order, given current understanding. It is not a storage unit for every idea anyone has ever mentioned.

The PM is responsible for:

- What enters
- What stays
- What leaves
- What order reflects current priorities
- Whether tickets remain understandable and current

Backlogs decay. Delete, rewrite, or reframe stale work before it enters delivery.

A smaller, current backlog is more useful than a comprehensive archive.

<Principle>
The backlog should clarify what might happen next. When it becomes an archive, it stops helping delivery.
</Principle>

Backlogs have system effects. A stale item is not harmless just because nobody is working on it. It can create false expectations, distract planning, preserve old politics, and make new work appear more negotiable than it really is.

## Truth, hypothesis, and noise

Backlog items should not all look equally real.

Separate:

- Work the team is committed to
- Options worth considering
- Hypotheses that need validation
- Requests that are only captured for reference

The backlog becomes dangerous when guesses, commitments, and stale ideas all wear the same uniform.

## Backlog does not mean commitment

Items in the backlog are options, hypotheses, and possibilities. They are not promises.

PMs need to actively communicate what is committed, what is likely, what is exploratory, and what is no longer relevant. Silence creates false expectations.

## Sunk-cost checks

Review old work with today's knowledge.

Ask:

- Would we start this now?
- What changed since this entered the backlog?
- Is the user problem still real?
- Is the solution still the best path?
- What is the cost of carrying this forward?

If the answer is weak, delete it or reframe it. Keeping stale work is not neutral. It taxes attention.

## Decision triggers

Some backlog items should carry explicit triggers:

- Promote when a customer/user signal appears
- Cut if the dependency does not resolve by a date
- Revisit after a related release
- Archive if no owner emerges

This keeps the backlog from becoming a waiting room for decisions nobody wants to make.

## The PM's core responsibility

The PM's job is not to keep the backlog full.

It is to protect focus, absorb pressure, say no when needed, and keep the system understandable.

A well-maintained backlog reduces risk, not just workload.
